Codex global skill catalog and specialist profiles

Problem and measured evidence

Codex emitted the skills-context truncation warning because the effective prompt exposed 125 skills. Physical plugin caches are not activation evidence; the denominator is the fresh codex debug prompt-input '' inventory. The failure mode is a root prompt carrying specialist and rare capabilities that should be routed only when needed.

The implementation must preserve every capability while reducing resident root context. It must also prevent a title-only Plane work item from being treated as execution-ready and remove the passive Orca hook, which forwarded events but discarded failures and could not enforce a decision.

Outcome and scope

  • Create the source-owned Codex catalog manifest with the exact 125-skill denominator, source roots, classification, and recovery coverage.
  • Install a compact root selection: 18 managed-global core skills plus 19 host-injected skills, yielding 37 visible skills. The other 88 managed-global skills are disabled at root only.
  • Render and install additive codex -p <profile> files for specialist and on-demand work; prove root and profile prompt inventories.
  • Make Accelerate require fresh catalog discovery before capability claims or thinning; export catalog configurations with provenance, digest, neutral-CWD validation, and rollback record.
  • Add a Plane MCP pre-creation readiness contract and receipt fingerprint binding; add a descriptor-visible mutation receipt template so callers cannot guess the hash field.
  • Replace the active Codex hook configuration with an explicit empty configuration after backup and contract test. This removes passive Orca behavior; it is not a claim that hooks now enforce policy.

Non-goals and hard boundaries

  • Do not delete skills, plugins, MCP servers, credentials, or caches.
  • Do not claim that native Codex profiles are credential, tool, sandbox, or MCP isolation. They are additive selection layers. Real isolation requires a separate CODEX_HOME/process and explicit trust boundary.
  • Do not promote a logical profile to a physical agent, change Plane project topology, close this issue, or use direct HTTP/borrowed credentials.
  • Do not treat a descriptor, configuration parse, or test green result as provider mutation/readback proof.
