## Conditional Accelerate entry

Preserve owner instructions and existing grants/refusals. Conversation, arithmetic,
explanation and clear bounded reversible low-risk edits proceed directly with
relevant verification; do not load a workflow or ask about setup for those requests.
Classify the behavior, not the layer: a login-button rule that rejects credentials
accepted by the backend/provider is authentication and compatibility work, not a
visual fast path. Applying signup policy to sign-in without matching authority is
a material decision. Copy/layout with unchanged admission can remain direct.

Surface/behavior invariant: UI wording never proves a change presentation-only; unresolved login admission authority requires inspection; a confirmed authentication or compatibility effect requires ASDS, continuing an accepted ASDS workflow instead of asking prematurely.
Continuity invariant: A current defect report is new intent evidence; an older plan may explain existing behavior but cannot silently close the request, so a confirmed conflict reopens or continues the same ASDS planning lineage.
Failure invariant: If the ASDS coordinator cannot actually be invoked, do not write fallback reassessments or mutate ASDS/OpenSpec planning state; report the capability block and preserve the package unchanged.
Evidence invariant: Static checks do not prove interactive behavior; blocked pertinent functional or browser evidence forbids claiming fixed, complete or accepted.
<!-- accelerate-entry-invariants:end -->

Repair invariant: A unique safely located but integrity-invalid ASDS package may be handed only to the validated planning-only ASDS coordinator with a signed locator that excludes untrusted revision and digest; ambiguous paths, multiple matches and application mutation remain blocked.
Review invariant: the qualified AGY 1.3.3 command-hook contract does not establish
trusted nested caller provenance or a canonical reviewer response binding. Permit the top-level coordinator
handoff, but fail closed on nested reviewer dispatch and never synthesize the
ASDS-required `agy-host-hook` receipt.

For new structured engineering work (material uncertainty, shared interfaces,
dependent outcomes or material effects), read the available Accelerate skill at
~/.gemini/config/plugins/accelerate-entry/skills/accelerate/SKILL.md before creating a plan. Pass the context
to spec-driven-superpowers (ASDS), which owns discovery and the reviewed planning
product, then releases ownership to a caller-selected implementation consumer.
If the owner explicitly selected ASDS directly, honor that selection.

Continue an accepted ASDS task or worker assignment with its existing coordinator;
do not re-triage or duplicate plans or approvals. Missing skills are a capability
limitation to report, not permission to install them or substitute a hidden workflow.
No rule here grants execution permission or initializes OpenSpec.
Static checks do not prove an interactive correction. Preserve missing functional
or browser evidence and never upgrade partial implementation into completion.
